# dynamodb-sam

An Amazon DynamoDB **Orders** table defined with AWS SAM and deployed to
**dev** and **prod** by two separate GitHub Actions pipelines. Each pipeline
uses its own S3 artifact bucket and IAM roles.

The pipeline resources (per-environment artifact buckets, pipeline execution
roles and CloudFormation execution roles) are created and managed only by the
separate [`dynamodb-sam-bootstrap`](https://github.com/muhumuza-ivan/dynamodb-sam-bootstrap) IaC repository,
as the stacks `dynamodb-sam-pipeline-dev` and `dynamodb-sam-pipeline-prod`.
This repo only consumes them.

[`.aws-sam/pipeline/pipelineconfig.toml`](.aws-sam/pipeline/pipelineconfig.toml)
is SAM's stage registry, the file `sam pipeline init` reads. It is generated
from those stacks' outputs by `dynamodb-sam-bootstrap/scripts/write-pipelineconfig.sh`,
so the ARNs in it are not maintained by hand.

## Table design (`template.yaml`)

| Requirement | Implementation |
|---|---|
| Primary key | `OrderId` (S), partition key |
| Additional attributes (≥2) | `CustomerId` (S), `OrderStatus` (S), `OrderDate` (S), plus `TotalAmount` (N) and `Items` (L), which are not indexed |
| GSI 1 | `CustomerOrdersIndex`: `CustomerId` (hash) + `OrderDate` (range), projection ALL |
| GSI 2 | `OrderStatusIndex`: `OrderStatus` (hash) + `OrderDate` (range), projection ALL |
| Billing mode | `PAY_PER_REQUEST` (On-Demand) |
| Storage class | `STANDARD_INFREQUENT_ACCESS` (not the default `STANDARD`) |
| Prod hardening | Point-in-time recovery and deletion protection are turned on only when `Environment=prod` |

Table name: `dynamodb-sam-<env>-orders`.

## Pipelines

| Workflow | Trigger | GitHub environment | Stack | Artifact bucket |
|---|---|---|---|---|
| `.github/workflows/pipeline-dev.yml` | push to `develop` | none | `dynamodb-sam-dev` | `dynamodb-sam-artifacts-dev-<acct>-<region>` |
| `.github/workflows/pipeline-prod.yml` | push to `main` | none | `dynamodb-sam-prod` | `dynamodb-sam-artifacts-prod-<acct>-<region>` |

Both workflows are split from the single workflow generated by `sam pipeline init`
(kept unmodified at [`docs/sam-generated-pipeline.yaml`](docs/sam-generated-pipeline.yaml)).
Each runs `sam validate --lint`, then `sam build`, then `sam package`, then
`sam deploy --role-arn <cfn exec role>`, using only its own stage's resources.

Authentication uses GitHub OIDC, so no long-lived AWS keys are stored.
Each pipeline execution role's trust policy accepts only one branch:
`refs/heads/develop` for dev and `refs/heads/main` for prod, of this repository only. The dev workflow
therefore cannot assume prod credentials. The jobs must not set a GitHub
`environment:`, because that changes the OIDC subject claim and the role
would reject it.

The repo uses GitHub's immutable OIDC subject format
(`repo:<owner>@<owner-id>/<repo>@<repo-id>:ref:refs/heads/<branch>`, see
`gh api repos/muhumuza-ivan/dynamodb-sam/actions/oidc/customization/sub`).
The bootstrap repo's trust policies match that format.

### Regenerating the pipeline

```sh
# in dynamodb-sam-bootstrap
GITHUB_ORG=muhumuza-ivan ./scripts/deploy.sh                # create/update buckets and roles
GITHUB_ORG=muhumuza-ivan ./scripts/write-pipelineconfig.sh  # write ../dynamodb-sam/.aws-sam/pipeline/pipelineconfig.toml

# in dynamodb-sam
sam pipeline init   # AWS Quick Start > GitHub Actions > stage 1 dev (dynamodb-sam-dev), stage 2 prod (dynamodb-sam-prod)
```

`sam pipeline bootstrap` is **not** used. With OIDC it always deploys its own
`aws-sam-cli-managed-<stage>-pipeline-resources` stack, because it has no
option to reuse an existing OIDC provider, and that would duplicate the
bootstrap repo's resources.
